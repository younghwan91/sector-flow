# 수급 지도(흐름 그림)·브랜딩·후원 — 설계

*2026-11-21 · 소유자 결정은 대화에서 받았다(아래 §1) · 시안 3종은 `docs/brand/concepts/{a-neon,b-editorial,c-bold}.html`(합성 데모)*

## 0. 한 줄

이 레포를 "오늘 누가 어느 섹터를 넘기고 넘겨받았나"를 **한 장의 움직이는 그림**으로 보여 주는 오픈소스 도구로
브랜딩하고 후원을 받는다. **도구는 공개하고, 실데이터 그림은 각자 자기 키로 자기 기기에서 본다.** 소유자도 지금처럼
비공개 웹에서만 본다. 공개 사이트·README·영상은 합성 데모로 만든다.

## 1. 의도와 결정(소유자)

- 목표는 **와우 팩터·바이럴·"성지"(투자에 관심 있는 사람이 모이는 오픈소스)** 다. 투자를 잘하게 하거나 종목을 고르게
  하는 것은 목표가 아니다.
- **후원을 받는다** — 오픈소스 코드·유지보수에 대한 자발적 후원(GitHub Sponsors). 후원했다고 더 보이는 것은 없다.
- **법적으로 가장 안전한 길로 간다.** 그래서 실데이터(섹터 합계 포함)를 공개하지 않는다. 근거:
  KRX 정보데이터시스템 약관(사전 허락 없는 복사·배포·공중송신 금지), KRX OpenAPI 약관(제3자 제공 금지),
  공공데이터포털의 KRX 시세(공공누리 4유형, 재배포 금지). 제약 없는 무료 출처는 없다(2026-11-21 조사).
- 실데이터 공개 사이트는 **KRX 서면 허락 또는 재배포 권리가 있는 이용권**을 얻은 뒤 별도 결정으로 덧붙인다.
  그때까지 공개 경로에 실데이터가 나갈 수 있는 길을 만들지 않는다(§6 검사).
- 시간순 변화(여러 날)를 보여 주는 것은 원한다 → 타임랩스(§3.3).

**비목표**
- 종목 단위 그림, 실시간, 알림, 계정·로그인, 댓글·채팅(유사투자자문 개정법이 겨냥하는 양방향 채널을 두지 않는다).
- 수익률·예측·점수·순위로 "고르게" 하는 장치.

**반목표(기술적으로 돌아가도 실패인 것)**
- 섹터 → 섹터, 주체 → 주체 연결이 그림·글·애니메이션 어디에서든 **함의**되는 것(§3.1).
- "유입·유출·몰렸다·쏠림·회전" 같은 말, 금칙어 표(`wording.py`) 위반.
- 공개 경로(Pages·README·이슈 템플릿·영상)에 실데이터 숫자·그림이 섞이는 것. 공식 채널이 사용자들의
  실데이터 그림을 모으거나 다시 올리는 것(갤러리 없음).
- 와우를 위해 잔차를 숨기거나 작은 값을 부풀리는 것.

## 3. 그림

### 3.1 관측된 것만 — 이분 그래프의 두 배치

원천은 `payload.json` 의 `flows[시장][섹터][주체][일]`(억원, 종가 환산 근사)다. 관측되는 것은 (날짜, 시장, 섹터, 주체)
순매수뿐이다. 2026-08-29 원장 설계(§2)가 이미 거부한 것을 그대로 지킨다: 섹터→섹터(돈에 꼬리표가 없고, 실측상
섹터는 같이 움직인다), 주체→주체(주변합 4개로 쌍별 이전량 6개가 정해지지 않는다), 잔차를 0 으로 밀기.

그래서 그리는 간선은 **(주체, 섹터) 하나하나**이고, 두 가지로 배치한다.

**보기 1 — 첫 화면 "넘긴 쪽 → 섹터 → 넘겨받은 쪽"**
```
 넘긴 쪽(순매도)          섹터               넘겨받은 쪽(순매수)
 개인     ════╗                         ╔════ 기관
              ╠══ 가상전자 −/+ 3,329억 ═╣
 기타법인 ════╝   가상기계 ...          ╚════ 외국인
 잔여     ──      (잔여는 별도 노드, 점선)
```
- 섹터 노드 높이 = 그 섹터의 순매수 합(Σ양수). 왼쪽 간선 합(Σ|음수|)과의 차 = 잔여(`−Σ4주체`)이고, 잔여 노드로
  **보인다**(원장 §2.3). 잔여를 4주체에 안분하지 않는다.
- **주체는 양쪽에 다 나온다**(빌더 확인, 설계자 결정): 왼쪽 `개인` = 개인이 순매도한 섹터들의 합, 오른쪽 `개인` = 순매수한
  섹터들의 합. 둘은 다른 숫자다(섹터 거울과 달리 정보가 겹치지 않는다). 주체 노드 순서는 양쪽 같게(개인·외국인·기관·기타법인·잔여).
- 섹터가 한 번만 나온다 — 세 시안이 모두 부딪힌 "양쪽 거울" 문제(같은 섹터가 같은 크기로 양쪽에)가 사라진다.
- 왼쪽 주체와 오른쪽 주체 사이에 **선이 이어지지 않는다**. 입자 애니메이션은 간선마다 따로 돈다: 왼쪽 간선의 입자는
  섹터 노드에서 사라지고, 오른쪽 간선의 입자는 섹터 노드에서 새로 난다(같은 입자가 노드를 통과하지 않는다 = 쌍을 함의하지 않는다).
- 글은 주변합만 말한다: "가상전자 — 개인 −2,927억 · 기관 +2,417억". "개인이 판 것을 기관이 받았다"는 쓰지 않는다.

**보기 2 — 주체를 누르면 "그 주체가 넘긴 섹터 | 넘겨받은 섹터"**
- 가운데 주체 하나, 왼쪽 순매도 섹터, 오른쪽 순매수 섹터, 주체의 순매수 합계는 꼬리(빗금)로. 같은 규칙: 입자는 주체 노드를
  통과하지 않고, 글은 "외국인이 A 를 넘기고 B 를 넘겨받았다"까지만 — "A 에서 빼서 B 에 넣었다"는 쓰지 않는다.
- 기관은 펼치면 세부 6종(`detail`)으로 갈라진다(투신·연기금 우선 표시 — 수급 신뢰 순서 규칙).

**공통**
- 시장: 전체 / 코스피 / 코스닥. 창: 1·5·20·60·120 거래일 누적(리포트의 기존 창).
- 꼬리 묶기: 목록 안 몫(gross 대비)이 문턱 아래인 섹터는 `기타 N개 섹터`. 문턱은 목록 안 몫으로 잡는다(비율 열 규칙).
  `(미분류)`·얇은 섹터(종목 수 `MIN_MEMBERS` 미만)는 흐리게(기존 규약).
- 단위·근사 표지: "억원 · 종가 환산 근사 · KRX 단독(넥스트레이드 제외) · 동시기 관측이며 예측이 아니다"(`basis.DATA_BASIS`).
- 증거 표지: 웹 `const EV` 에 `map` 항목(사실 관측, 검정 대상 아님).

### 3.2 모양 — 시안 A(입자) + B(신문 문법)

- 웹 첫 화면은 A 의 어두운 바탕·빛 입자(밤), 헤드라인·숫자 띠·주석·카드는 B 의 신문 문법. 라이트/다크 둘 다,
  `prefers-reduced-motion` 이면 정지 그림.
- 색: 넘긴 쪽 파랑, 넘겨받은 쪽 빨강(국내 관례) + 부호·▲▼·열 제목 — 색만으로 구분하지 않는다.
- 헤드라인은 `sectorflow.summary` 의 순위·극단·가장 큰 주체를 **그대로** 쓴다(다이제스트와 같은 규칙, 다시 정하지 않는다).
  C 의 조사 자동 처리(은/는·으로/로)는 가져온다.
- 글꼴은 OFL 만(Noto Sans KR·Noto Serif KR 등). 기존 템플릿처럼 Google Fonts `<link>` 로 부르고, 설치본(wheel)은
  `offline_templates.strip_remote` 가 떼어 시스템 글꼴로 떨어진다 — 글꼴이 없어도 그림이 깨지지 않게 폭을 글꼴에 기대지 않는다.

### 3.3 타임랩스

- 날짜 막대 + 재생: 보기 1·2 를 하루씩(또는 5일 이동합) 넘기며 띠가 모양을 바꾼다(노드 정렬은 구간 전체 기준으로
  고정해 깜빡이지 않게).
- 영상: 배치는 만들지 않는다(무겁다). `scripts/map_video.py` 가 데모 또는 자기 리포트로 MP4·GIF 를 뽑는다(Playwright 녹화 + ffmpeg).

### 3.4 공유 카드

- `map.png`(1080×1350) 과 `map_wide.png`(1200×675) — 배치가 Playwright 로 찍는다(`digest.py` 의 Chromium 경로를 쓴다).
  카드에도 단위·근사·출처 줄이 들어간다. 데모 카드에는 `[합성 데모]`.
- 카드는 **자기 폴더 안의 파일**이다. 밖으로 보내는 기능은 만들지 않는다(다이제스트와 같다).

## 5. BYO — "자기 키로 첫 그림까지"

공개 전략의 중심이다. 지도는 수급(`flows`·`detail`)만 쓰므로 **지도 전용 수집**(`ka10099` 종목·업종 + `ka10059` 수급, 종목당
약 1회)과 **수급만으로 짓는 페이로드**(`sector_flow.py --flows-only`)를 둔다 — 전체 TR 6종 백필(종목당 약 6회 ≈ 전 시장 15시간)을
기다리지 않고 약 2.5시간에 첫 지도가 뜬다. 수급 금액은 Phase 1 에서 kr_quant 와 **차 0**(두 섹터 96종목)이었고, 수급 지도는 수익률을 쓰지
않으므로 Phase 2 의 수익률 불합격은 이 그림을 막지 않는다(수익률 칸은 BYO 에서 "근사" 표지).

- 전 시장(약 2,500종목) 백필·일일 증분, 키움 호출 상한(초 5·분 100·시간 1,000) 준수, 중단 재개.
- sqlite → 리포트 폴더 → `map.html` 이 TimescaleDB 없이 끝난다.
- 온보딩 문서: 키 발급 → `uvx`/`uv tool install` → 첫 그림. 각자 데이터의 이용 조건은 각자 약관을 따른다는 고지.

## 6. 법적 안전장치(코드로 지킨다)

1. **공개 산출물 검사**: `site/`·README·`docs/images/` 의 그림·데이터가 데모에서만 나왔는지 — 데모 표지(`DEMO_NOTICE`)와
   `가상` 섹터명만 있는지 검사한다(`tests/`). 실데이터 섹터명(벤더 분류 26개)이 공개 경로에 나오면 실패.
2. **금칙어**: 새 페이지·카드·랜딩·README 를 `wording.py` 로 검사. 브랜드 문구에 쓰지 않을 말(유입·유출·몰림·쏠림·회전·성지)을
   추가 검토한다 — "성지"는 내부 목표어이지 화면 말이 아니다.
3. **고지**: 랜딩·README 에 "투자 조언 아님 · 각자 데이터 이용 조건 · 권리자 요청 시 즉시 조치(연락처)".
4. **추적 없음**: 랜딩에 분석 스크립트·쿠키 없음(검사).
6. **말 목록**: 새 화면이 피할 말(유입·유출·몰림·쏠림·회전)은 `wording.py` 안에 별도 튜플(`MAP_AVOID`)로 두고 지도·카드·랜딩에만
   적용한다. 기존 화면의 같은 말은 바꾸지 않는다(그 자리 뜻이 다르고 — 로그 회전 등 — 표는 여전히 한 파일이다).
5. CLAUDE.md·README 의 "수익화 안 함" 줄을 "오픈소스 후원은 받는다, 실데이터는 공개하지 않는다"로 고친다.

소유자만 할 수 있는 것(코드 밖): KRX 문의 · 소셜 미리보기 업로드 · GitHub Sponsors 가입. 문의 초안 등 소유자용 메모는
레포에 두지 않는다(공개 레포).

## 7. 접근(고른 것과 버린 것)

**공개 방식**
1. 실데이터 공개 웹 + 카드 — 와우 최대. 약관 회색 지대라 **버렸다**(소유자: 가장 안전한 길).
2. 실데이터 이미지·영상만 공개 — 1번과 같은 문제. **버렸다.**
3. **도구 공개 + 그림은 각자(채택)** — 법적으로 깨끗하고, 후원·브랜딩이 그대로 산다. 바이럴은 데모 영상·도구 자체가 맡는다.

**그림 구조**
1. 주체 넷을 합친 "순매도 섹터 → 주체 → 순매수 섹터" — 시안 3종이 그렸다. 섹터당 4주체 합 ≈ 0 이라 양쪽이 거울이 된다. **버렸다.**
2. 원형 코드 다이어그램(섹터↔섹터) — 관측되지 않은 짝. **버렸다.**
3. **보기 1(주체→섹터→주체) + 보기 2(주체별)(채택)** — §3.1.

**모양**: A(네온 입자)·B(신문)·C(K-볼드) 중 A+B. C 는 과열된 말투로 읽힐 수 있어 법적 안전 기준과 어긋난다. 조사 처리만 가져온다.

## 9. 정한 것(빌더 확인 뒤 설계자 결정 — 소유자가 "알아서" 위임)

- **브랜드 이름은 `sector-flow` 그대로**, 한국어 설명어 "수급 지도"를 붙인다. 레포·패키지·명령(`sw-flow` 등)·크론 경로는 바꾸지 않는다.
  바꾸는 것은 보이는 것(워드마크·색·글꼴·말투)뿐이다.
- 설치는 PyPI 없이 git URL: `uv tool install git+https://github.com/younghwan91/sector-flow`.
- **지도는 새 페이지**다. 비공개 웹의 첫 화면(사실 요약 규칙)은 그대로 두고 색인·뷰어에서 잇는다. 기존 페이지·TUI 는 다시 꾸미지
  않는다 — 머리의 워드마크 정도만 맞춘다. 터미널 지도는 이번 범위 밖.
- **BYO 첫 실행**: 지도에 필요한 TR 만 받는 빠른 길(`--map-only`, 기본 120거래일)을 기본으로 하고 전체 백필은 이어 받기로.
  완료 확인은 Phase 1 처럼 섹터 두 개 조각으로, 배치 시간을 피해 `busy.py` 를 지키며 돈다(전 시장 실행은 완료 조건이 아니다 —
  quant-airflow 와 같은 키의 호출 예산을 쓴다). 자기 키로 자기 데이터를 받는 것은 약관상 통상 이용이라 문서 공개를 막지 않는다.
