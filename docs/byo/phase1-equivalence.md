# BYO Phase 1 — 자기 키 sqlite 와 kr_quant 의 리포트 숫자 대조

실측 2026-11-08(일) 17:05~17:20 KST. 설계는 BYO 타당성 문서 §2·§6 P1 이다. 그 문서는 아직 main 에 없고
브랜치 `younghwan91/strategy-a-plus` 의 `docs/strategy/byo-feasibility.md`(커밋 1b02f66)에 있다. 아래 "설계 §N"은 그 문서의 절이다.

**완료 조건(타당성 문서 (a)·(b), 이 조각에 한정).** 같은 기준일에 BYO sqlite 로 만든 `payload.json` 이 kr_quant 판과
- 섹터×주체 순매수 금액의 상대오차가 0.5% 이내이고,
- 섹터 수익률 차가 0.05%p 이내이며,
- 완전성 관문(`scripts/completeness_gate.py`)을 그대로 통과한다.

## 결론

범위: **확정치 백필**(일요일 수집 대 kr_quant 토요일 확정분)과 **두 섹터 96종목**이다. 평일 18:10 잠정치끼리의 일치는 시험하지 않았다.

수익률 차는 **전부 상장주식수 표**에서 나온다. BYO sqlite 의 주식수 표만 kr_quant 것으로 바꾸면(아래 H1) 모든 창·모든 끝날에서
최대 0.004%p 로 줄고 시총이 완전히 같아진다. 오차는 창 앞부분(2025-10~12)에 몰려 있다. 기준일에서 끝나는 5·20·60일 창은 차가
0.042%p 이하이지만, 이것은 오차가 몰린 곳을 피한 우연일 뿐 시드로 충분하다는 증거가 아니다.

결론: **(확정치·이 조각에서) 수급과 지수는 키움 키 하나로 kr_quant 와 같다. 섹터 수익률은 시드(대안 B)로는 바를 못 맞춘다.**
H1 이 맞춘 기준은 "DART 분기값 + 키움 주간 스냅숏"이다. 주간 스냅숏은 BYO 가 과거로 거슬러 받을 수 없다. 그래서 H1 은 상한일 뿐이고,
DART(대안 A)만으로 바를 맞추는지는 **미확인**이다.

**유니버스를 좁힌 방법.** 리포트 코드에 종목 필터를 넣지 않았다. kr_quant 에서 같은 섹터 종목의 행만 **읽어** 같은
`storage.SCHEMA` sqlite 로 옮겼다(`equiv slice`). 두 쪽이 같은 코드 경로(sqlite)로 리포트를 만들므로 차이는 데이터에서만
나온다. 섹터의 종목을 전부 담았으니 섹터 합계는 전체 유니버스 리포트의 그 섹터 값과 같아야 한다. 실제로 kr_quant
전체(Postgres) 리포트의 두 섹터 칸과 조각 리포트는 flows·`iret`·`ret` 이 모두 **차 0** 이었다(`compare --full`). 조각 추출이
숫자를 바꾸지 않았다는 검산이다. 이 검산의 범위는 flows·`iret`·`ret` 뿐이다(cap·names·today·수치표는 대조하지 않았다). 또 양쪽이 같은 `stocks`
소속을 쓰므로 유니버스 차이는 원리적으로 잡지 못한다.

### 시드 주식수의 kr_quant 대비 시총 차 (설계 §3 대안 B)

기준값인 kr_quant 주식수도 근사다. 창 시작일(2025-10-16)에 as-of 로 잡히는 행이 95종목 중 92종목에서 2024-12-31 DART 값이다.
그다음 행은 2025-12-31 DART 값과 2026-07-09 부터의 키움 주간 스냅숏뿐이다. 그래서 아래는 "시드의 오차"가 아니라 "kr_quant 와의 차"다.

리포트 창의 (종목, 날짜) 25,002칸에서 시총 비 BYO/kr_quant 를 쟀다. 중앙값은 차가 거의 0(0.0006%)이다. p90 14%, p95 52%,
p99 164%, 최대 374%(012170)다. 96종목 가운데 37종목이 어느 날이든 1%를 넘게 벗어났다.

크게 벗어난 종목은 모두 **병합·감자와 유상증자가 겹친 소형주**다. 시드는 현재 주식수에 수정주가 이벤트(분할·병합·감자)만
거꾸로 적용한다. 그래서 그 사이의 유상증자·CB 전환·소각을 못 본다.

그래서 BYO 기록기(`collect/write.py`)가 조정 표에 `open·high·low` 열을 더해 채우게 했다. 이 실측 DB 는 수집기를 다시 돌리지 않았다(호출 절약). 대신 같은 응답으로 이미 저장된 `daily_bars` 의 OHL 로 채웠다(수집기도 같은 응답 행을 두 표에 쓴다). 채운 뒤에는 B 검사가 통과한다. 기록 경로 자체는 `tests/test_collect_backfill.py` 가 본다.

## 수집기 구성 (`src/sectorflow/collect/`)

- `kiwoom.py` — 표준 라이브러리 `urllib` 만 쓴다. `kiwoom-client` 는 주문 API 를 담고 있어 import 하지 않는다.
  허용 TR 6개 밖의 `api-id` 는 요청 전에 거부한다. 무효 토큰(HTTP 200 + `return_code 3`)이 오면 한 번만 재발급하고,
  다시 오면 `TokenConflict` 로 멈춘다. 429·`return_code 5` 는 백오프한다. 연속조회는 응답 헤더로 하고, 호출 상한을 둔다.
- `fetch.py` — 파싱은 quant-airflow 와 한 글자씩 같다(`to_int` 빈 값 → 0, 가격 절댓값, 천 주 단위).
- `write.py` — `storage.SCHEMA` 에 `collect_runs`(원장)·`shares_provenance`(seed/kiwoom)를 더한다. 스키마 판은 `PRAGMA user_version` 이다.
- `shares.py` — 시드 = 현재 × exp(C(시드일) − C(스냅숏일)). `market_cap_asof_bulk` 와 왕복 항등은 테스트로 고정했다.
  `reseed` 는 호출 없이 다시 계산한다.
  - 실측 중 버그 하나를 잡았다. 수정·무수정 응답이 같은 이벤트를 둘 다 실어서, 처음 판은 이벤트를 두 번 곱했다.
  - 이 실행의 시드는 `reseed` 로 고친 값이다. 바뀐 시드는 18종목이고, 분할·병합·감자 이벤트가 있는 종목 18개와 정확히 같다.
- `equiv.py` — 조각 추출·원표 대조·페이로드/수치표 대조. `slice` 는 `--out` 이 이미 있으면 `--force` 없이 지우지 않는다.
- `busy.py` — 운영 창(위 절). ka10059 가 쪽 상한에서 잘리면 실패로 센다. 상장이 늦어 이력이 짧은 것은 실패가 아니라 원장 메모(`collect_runs.notes`)로 남긴다.
  `corporate_actions` 는 응답이 덮은 날짜 범위만 바꾼다(증분 실행이 과거 분할·병합을 지우지 않게).
- 패키징: wheel 이 `scripts/` 를 담지 않던 문제는 `force-include` 로 풀었다. 리포트 생성기 네 개와 템플릿을
  `sectorflow/_scripts/` 로 복사하고, 진입점 `sector-flow-payload`·`-numbers`·`-gate`·`-verify`·`-collect` 를 추가했다
  (`src/sectorflow/report_cli.py`). 레포 체크아웃에서는 같은 진입점이 `scripts/` 원본을 돌린다.
  확인한 것: `uv build --wheel` 로 만든 wheel 을 `uv tool install` 로 임시 도구 폴더에 설치했다. 레포 밖 폴더에서
  `sector-flow-payload`·`-numbers`·`--from-json`(viewer)·`-gate` 가 이 조각 DB 로 돌았고, 그 `flows` 는 레포 실행본과 바이트까지 같다.

## 운영 창 — 같은 앱키를 나눠 쓸 때

키움은 앱키 하나에 토큰 하나다. 같은 키로 따로 로그인하면 앞 토큰이 무효가 된다(`8005`). 그래서 매매 봇·다른 수집기와 키를
나눠 쓰면 **서로 죽인다.**

- **창은 호스트별 설정 파일이다**(`--busy-file`, 환경변수 `SECTORFLOW_BUSY_FILE`).
  - BYO 사용자의 기본값은 빈 목록이다. 이때 "같은 키를 다른 프로그램과 쓰면 토큰이 충돌한다"는 경고를 띄운다.
  - 이 호스트의 창은 `deploy/kiwoom_busy.simnode.toml` 이다. quant-airflow DAG 스케줄과 scalp-it 크론을 읽기 전용으로 확인하고,
    Airflow 로그로 소요 시간을 재서 만들었다.
    - 평일 08:45~20:00
    - 화~토 06:25~07:45
    - 토 09:55~11:00
    - 일 10:55~12:30
  - `weekly_delisted_stocks`·`monthly_listed_shares_backfill` 은 krx·naver·dart 만 써서 창에 넣지 않았다.
- **검사는 요청(토큰 발급 포함) 직전마다** 한다.
  - 처음 판은 시작할 때 한 번만 봤고, 창도 평일 06:30~07:30·15:30~19:30 두 개뿐이었다. scalp-it 장중 수집(08:55~15:40)과
    주말 DAG 를 몰랐다.
  - 이제 긴 백필이 창 안으로 들어가면 그 요청을 보내지 않고 멈춘다(종료코드 75). 끝난 종목은 커밋돼 있고 `backfill --resume` 이
    이어 받는다(`collect_done` 표).
- **토큰 재발급은 한 실행에 2회까지다.**
  - 처음 판은 요청마다 1회씩 허용해, 같은 키를 쓰는 다른 프로그램과 끝없이 서로 밀어낼 수 있었다.
  - 상한을 넘으면 `TokenConflict` 로 멈춘다.

## 네트워크 불변식 (설계 §4.2)

이 도구는 아래를 하지 않는다. `tests/test_packaging.py` 가 고정한다.

- **목적지는 `api.kiwoom.com` 하나다**(DART 를 붙이면 그때 하나 더한다).
  - 설치본에 실리는 코드(`src/sectorflow/**`, wheel 에 복사하는 `scripts/*.py`)의 URL 호스트는 이것뿐이다.
  - 네트워크 라이브러리는 표준 `urllib` 만 쓴다.
- **중앙 서버 중계는 없다.** 판매자 서버가 키움을 대신 부르거나, 사용자 데이터를 받아 가공해 돌려주지 않는다.
- **공유 캐시·시드 DB 배포는 없다.** 설치본에 미리 받은 sqlite·샘플 데이터를 넣지 않는다. 테스트 픽스처는 합성 데이터다.
- **텔레메트리는 없다.** 사용 통계·오류 자동 보고를 하지 않는다.
- **설치본 HTML 은 밖으로 요청하지 않는다.**
  - 레포 템플릿은 Google Fonts 를 불러온다. wheel 빌드 훅(`hatch_build.py`)이 그 `<link>` 를 뗀 사본을 파일 하나씩 싣고,
    글꼴은 시스템 글꼴로 떨어진다.
  - 남는 것은 사용자가 눌러야 열리는 문서 링크(`<a href>`)뿐이다.
- **kr_quant 와 연결하지 않는다.**
  - 수집기 기록기는 Postgres DSN 을 거부한다.
  - `equiv slice` 는 이 시험을 위해 이 호스트에서만 쓰는 읽기 전용 도구다.
