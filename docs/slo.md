# SLO — 언제까지 나와야 "제때"인가

리포트 배치(README §3)의 서비스 목표다. 측정은 전부 운영 사건 원장 `reports/events.jsonl` 로 한다 —
폴더 바꿔 끼우기가 흔적(INCOMPLETE·mtime)을 지우고 `cron.log` 는 5MB 에서 돌아, 원장 없이는 나중에 잴 수 없다.
형식·통계는 [`scripts/ops_ledger.py`](../scripts/ops_ledger.py) 머리말, 쓰는 쪽은 `daily_report.sh`·`cron_run.sh`·`serve.sh`([`scripts/_ledger.sh`](../scripts/_ledger.sh))와
`freshness_check.py` 다. 원장은 웹 허용 목록에 없다 — 밖에 안 보인다.

| 항목 | 목표 | 근거 |
|---|---|---|
| 첫 게시 | 거래일 당일 **18:30 KST** 까지. 모드를 묻지 않는다 — 다음날 08:25 확정 모드가 처음 게시했으면 늦은 날이다 | 18:10 크론 + 빌드 2~5분. 19:10 은 재시도라 그때 게시되면 이미 늦은 날이다 |
| 확정 재생성 | 다음날 **08:40 KST** 목표, **10:40 KST** SLO | 08:20 확정 모드 + 빌드. `daily_finalize` 가 늦은 날은 10:20 재시도가 받는다 — 10:40 을 넘기면 위반 |
| 웹 가용 | 5분 프로브(`/healthz`)가 **200** | `serve.sh` 크론이 5분마다 묻고 원장에 `probe` 사건을 남긴다(닿지 못하면 `status: null`). 서버가 내려가 있던 주기는 줄 자체가 없다(그 주기는 재기동) — "프로브 중 200 비율"은 표본 안의 응답률이지 가용률이 아니다. 표본(회수·범위·창 대비)과 공백(빈 5분 칸)을 같이 적는다 |

코드의 정본 상수는 `ops_ledger.PROV_SLO_KST`·`FINAL_TARGET_KST`·`FINAL_SLO_KST` 다(이 표와 같다 —
`tests/test_ops_ledger.py` 가 대조한다).

**분모**: 거래일이다 — `scripts/krx_calendar.py`(2026 은 DB 실측 대조, 2027 은 KRX 공지 전 잠정). 원장에 나온 날로 세면 크론이
안 돌았거나 DB 가 끊겨 `asof` 가 없는 날이 분모에서 빠져 "놓친 날 없음" 이 된다. 칸은 제때(그중 검증 통과) · 늦음 · 미게시 ·
기록 없음(복원된 재구성뿐) · 원장 도입 전(재지 않았다) · 기한 전. 달력 밖 평일은 분모에 넣지 않고 그 수를 적는다.

**감시**: 평일 20:30 `freshness_check.py` 가 전 거래일을 원장으로 잰다. 기한을 넘긴 첫 게시·확정, **미게시**, 원장이 돌고 있었는데
실행 기록이 빈 날(크론이 안 돌았거나 쓰기가 실패했다), 한 시간 넘게 끊긴 프로브는 경고(75, 할 일은 README §3.1)다. 원장이 그 뒤에
시작된 날만 재지 않는다고 적는다. 전 거래일은 달력이 정한다 — DB 의 마지막 수급일로 물으면 수집이 통째로 빠진 날이 사라진다.

**집계**: `uv run python scripts/ops_ledger.py`(최근 30일, `--days 90`·`--json`) — 게시 준시성, 관문 차단, 검증 실패,
확정 지연, 재구성·정정, 프로브 표본·공백, 못 읽은 원장 줄 수. `--errata` 는 첫 게시 뒤 숫자가 바뀌었을 수 있는 게시를 한 줄씩(시각 포함) 나열한다 —
재구성, 첫 확정의 칸 변경, 그 밖의 2번째 게시부터(재게시·검증 실패 뒤 재생성, `payload_sha` 가 같으면 뺀다).

**백필(한 번)**: 원장 도입 전의 과거는 남아 있는 것(cron.log·폴더 표시 파일·`.archive`)에서
`uv run python scripts/ops_ledger.py --backfill` 로 복원했다. 그 사건들은 `source: "backfill"` 이 붙는다 —
시각이 mtime 기반인 줄도 있어(재생성마다 리셋) 통계가 출처를 따로 센다. 두 번 돌리면 거부한다(`--force` 로만 추가).
완전성 관문이 생기기(2026-11-02 19:07, `ops_ledger.GATE_SINCE`) 전의 게시에는 관문 결과가 없다 — `gate: null` + `관문 도입 전`. 예전 백필이
`gate: "pass"` 로 박아 이미 들어간 줄은 고치지 않고 읽을 때 같은 뜻으로 푼다.
