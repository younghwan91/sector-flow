# 지표 검증 사전등록 — 데이터·계산·신빙성 (2026-11-08)

결과를 보기 전에 질문과 합격선을 고정한다. 결과가 나온 뒤 기준을 바꾸지 않는다. 바꿔야 하면
이 문서에 날짜와 이유를 덧붙이고, 원래 기준의 판정도 같이 적는다.

기존 `verify_report.py`(A~H 계층)는 "정의대로 계산됐는가·화면이 맞게 그리는가" 를 본다.
이 검증은 그 바깥 — **독립 구현으로 다시 만들어도 같은가, 그리고 그 숫자를 믿을 수 있는가** — 를 본다.

## Q1. 데이터 — 원자료에서 독립으로 다시 만들어도 페이로드와 같은가

- 대상: `reports/2026-11-06/payload.json` 의 섹터×시장×주체×일 순매수, 거래대금, 시총, 섹터 수익률.
  과거 게시본 3개(2026-09-15, 2026-10-15, 2026-11-02)도 그 기준일로 다시 만든다.
- 방법: 레포 코드를 import 하지 않고 DB(`kr_quant`, 읽기 전용)에서 정의(README §7)대로 다시 계산한다.
  표본 손검산은 `haiku-verifier` 10~20개가 따로 한다.
- 합격: 2026-11-06 은 셀의 99.9% 이상이 반올림 폭(0.1억, 수익률 0.001%p) 안. 넘는 셀은 전부 원인을 댄다.
  과거 게시본은 차이를 (a) 확정치 덮어쓰기 (b) 그 밖으로 나누고 (b) 가 0 이어야 한다.

## Q2. 계산 — 페이로드에서 정의대로 다시 계산해도 표와 같은가

- 대상: `numbers.html` 의 12블록(5·20·60·120 × 전체·거래소·코스닥) 전 셀과 종합 G. 날짜 3개.
- 방법: `sector_numbers.py` 를 보지 않고 README §7 과 `docs/kqflow-formulas.pdf` 의 정의만으로 구현.
- 합격: 모든 셀이 표시 자릿수 반올림 안. k·b·t 는 1e-3 안. 불일치는 전부 원인(정의 문서 vs 코드 중 어느 쪽이 틀렸나).

## Q3. 신빙성 — 그 숫자를 믿을 수 있는가

### 3a. 잠정치 민감도
- 게시 리포트의 마지막 날은 잠정치다(확정은 다음날 06:30). 게시본 vs 같은 기준일을 확정 데이터로 다시 만든 것.
- 지표: 섹터 가속(20일) 부호 바뀜 비율, 가속·G 순위 Spearman, G 통과 집합 변화.
- 합격("게시본을 믿어도 된다"): 기준일의 90% 이상에서 Spearman ≥ 0.95 이고 G 통과 집합 변화 ≤ 1섹터.

### 3b. 금액 근사(수량 × 종가)
- 비교: 수량 × 종가 vs 수량 × VWAP(거래대금 ÷ 거래량). 섹터·구간 단위.
- 합격: 섹터 20일 임펄스의 |상대차| 중앙값 ≤ 5% 이고 순위 Spearman ≥ 0.95.

### 3c. 추정의 안정성(기술 통계, 합격선 없음)
- k 의 t 분포(창·시장별, 날짜별), |t| < 2 비율. x 와 −Δv 의 상관. G 세 성분의 중복.

### 3d. 앞날과의 관계(기술 통계 — 알파 심사가 아니다. 알파 판정은 swing-it 소관)
- 시점 정합: 각 기준일의 지표는 그날까지의 데이터만으로 계산. 앞날 수익률은 섹터 자체 바구니 수익률.
- 지표: 20일 가속(기관), x, G, 20일 기관 임펄스. 앞날 5·20거래일.
- 통계: 날짜별 횡단면 순위 IC. 표본은 앞날 구간이 겹치지 않게 지평 간격으로 뽑는다.
  널은 날짜 안에서 섹터 라벨을 섞은 1000회. 10종목 미만 섹터 제외.
- 판정("관계가 있다"): 평균 IC 의 부호가 널 대비 p < 0.05 이고 표본 전·후반에서 같은 부호.
  아니면 "증거 없음". 섹터가 27개뿐이라 검정력이 낮다는 것을 같이 적는다.
- 비용·집행을 넣지 않으므로 이 결과로 매매 판단을 하지 않는다.
